# Макеты → UI

## 1. Где лежат макеты

```
mockups/
├─ overview.png              # обзор всех экранов
├─ sheet-player.png          # путь игрока
├─ sheet-admin-tv.png        # админ + ТВ
├─ sheet-history.png         # история
├─ 01-board.html/.png        # 780×1688 (2x), телефон
├─ 02-rooms.html/.png
├─ 03-nick.html/.png
├─ 04-player-buzz.html/.png
├─ 05-player-verdict.html/.png
├─ 06-admin.html/.png
├─ 07-tv.html/.png           # 1920×1080
├─ 08-history.html/.png
├─ 09-match.html/.png
├─ styles.css                # токены и стили макетов
└─ build_sheets.py           # пересборка листов
```

Макеты — **дизайн-референс**, не прод-код. В сборку приложения и ZIP они не попадают.
HTML-исходники читать полезнее, чем PNG: там точные размеры, отступы и состояния.

## 2. Дизайн-токены

| Токен | Значение |
|---|---|
| Фон | `#0b0f1a` |
| Поверхность | `#141a2b` |
| Текст | `#e8eefc` |
| Акценты | cyan `#22d3ee`, lime `#a3e635`, amber `#fbbf24`, rose `#fb7185` |
| Радиусы | карточки 16–24 px, кнопки 14–20 px |
| Тени | мягкие, без жёстких чёрных обводок |
| Анимации | 150–250 мс, `prefers-reduced-motion` уважать |

- Тёмная тема по умолчанию (светлая — P1).
- Шрифт: `system-ui, "Segoe UI", Roboto, sans-serif`. **Никаких Google Fonts и CDN.**
- Иконки: инлайн SVG или эмодзи. Никаких icon-библиотек.
- Цвет игрока — детерминированно из палитры 8–10 цветов (по индексу/хэшу ника).
- Тайминги и очки: `font-variant-numeric: tabular-nums`.
- В Tailwind 4 токены задаются в CSS через `@theme`, а не в `tailwind.config.js`.

## 3. Брейкпоинты

| Диапазон | Что оптимизируем |
|---|---|
| 360–430 px | телефон, главный приоритет |
| 768 px | планшет |
| 1280+ | ноутбук/десктоп |
| 1920+ | ТВ-табло |

Проверки: 360×640 — нет горизонтального скролла; 390×844 — основной мобильный; 1920×1080 — читается с дивана.

## 4. Экран → маршрут

| Макет | Маршрут | Компоненты |
|---|---|---|
| 01-board | `/` | `BoardPage`, `GameCard` (game / link / soon), счётчик комнат |
| 02-rooms | `/game/:gameId` | `RoomsPage`, `RoomRow`, «Создать комнату» |
| 03-nick | модалка в 02 | `Modal`, `NicknameInput` (2–20, trim, ошибка «ник занят → Ник2») |
| 04-player-buzz | `/r/:code` | `PlayerRoomPage`, `BuzzButton`, `QueueList`, `PlayersList` |
| 05-player-verdict | `/r/:code` | `RoundResult`, `VerdictBadge` |
| 06-admin | `/r/:code` при `adminKey` / `/admin/:code` | `AdminRoomPage`, `AdminControls`, `VerdictButtons`, `QuestionEditor` |
| 07-tv | `/r/:code/display` | `DisplayPage` без контролов, крупная типографика |
| 08-history | `/history` | `HistoryPage`, `MatchCard`, пагинация по 20 |
| 09-match | `/history/:matchId` | `MatchPage`, итоговая таблица, раунды |

На макетах ник ведущего «Игрок 1» стоит и в очереди игроков — это иллюстрация, что админ тоже играет.

## 5. Огромная кнопка «Я знаю!»

Обязательные свойства в фазе `buzz_open`:

- Занимает нижнюю треть экрана, `min-height: 32vh` (на телефоне допустимо 40%).
- Крупный шрифт (`clamp`), вес 700+, контраст AA.
- `touch-action: manipulation`, `user-select: none`, отключён двойной тап-зум.
- `overscroll-behavior: contain`, учтён `env(safe-area-inset-bottom)`.
- Тач-цели ≥ 44×44 px; основной сценарий — одной рукой.
- Вибрация `navigator.vibrate(30)` при нажатии (если поддерживается).
- До `openBuzz` кнопка неактивна с подписью «Ждите сигнала».
- После нажатия превращается в статус: «Вы №2 · +0.42 с» + очередь ниже.
- Оптимистичный отклик допустим **только** для кнопки; очки и порядок — с сервера.

## 6. Очередь раунда

Каждая строка: место (1, 2, 3…), ник, отставание (`0.00 с` у лидера, `+0.42 с` у остальных), статус (ждёт ответа / отвечает / верно ✓ / неверно ✗). Лидер подсвечен. Тайминги — моноширинный `tabular-nums`. `aria-live="polite"` на контейнере очереди и счёта.

## 7. ТВ-режим

- Отдельный URL `/r/:code/display`, без кнопок управления.
- Типографика `clamp(18px, 1.6vw, 34px)`, вопрос крупно.
- Видны: вопрос, гонка ответов, таблица очков, QR/адрес для подключения (P1).
- Автообновление по WS, без скролла и без мыши.

## 8. Мелкие, но обязательные правила

- Русский UI, все строки в `src/shared/i18n/ru.ts`; код и комментарии — на английском.
- Пустые состояния и скелетоны; понятные ошибки («Не удалось подключиться. Проверьте, что телефон в той же Wi-Fi сети»).
- Видимый `focus-ring`, семантические кнопки, контраст AA.
- Бандл < 400 КБ gzip: никаких тяжёлых зависимостей.
- Звуки (P1) — Web Audio, без аудиофайлов; переключатель, дефолт «вкл».
- Wake Lock (P2), переподключение — баннер «Восстанавливаем соединение…».

## 9. Как проверять визуал

1. Снять макет: `mockups/<номер>-*.html` открыть локально или сравнить с PNG.
2. Запустить приложение и открыть страницу во встроенном браузере (скилл `browser`).
3. Проверить вьюпорты 390×844 и 360×640: горизонтальный скролл, доступность кнопки большим пальцем.
4. Проверить 1920×1080 для админки и ТВ.
5. Сверить: состав блоков, иерархия, размер кнопок, плотность — не пиксели.

Пиксельного соответствия не требуется, но состав экранов и логика блоков должны совпадать с ТЗ.
