## 1. Что это

Игра для живого мероприятия в локальной сети, у одного телевизора/проектора.

1. На Windows-ноутбуке запускается сервер (`start.bat` или `npm start`).
2. В консоли печатаются адреса вида `http://192.168.1.10:3000` — их открывают с телефонов.
3. Одна игра: «Кто быстрее». Никакого борда и списка игр.
4. Игрок создаёт комнату и вводит ник → он ведущий. Остальные входят по 4-символьному коду.
5. Ведущий читает вопрос вслух, нажимает «Принимаю ответы».
6. У игроков появляется большая кнопка «Я знаю!». Первый нажавший — первый в очереди, остальные ниже с отставанием `+0.42 с`.
7. Ведущий ставит «Верно +1» или «Неверно». Неверный уходит в конец очереди и может нажать снова.
8. Ведущий завершает игру → итоговая таблица и запись в историю.
9. История хранится в JSON-файле и доступна по `/history`.
10. Всё работает офлайн, без аккаунтов, CDN и внешних API.

## 6. Игровая логика

### 6.1 Фазы

```
lobby → question → buzz_open → result → question → … → finished
```

| Фаза | Игрок | Ведущий |
|---|---|---|
| `lobby` | видит список, ждёт | «Начать игру» |
| `question` | «Слушайте вопрос», кнопка неактивна | поле вопроса, «Принимаю ответы», «Завершить» |
| `buzz_open` | жмёт «Я знаю!» один раз | «Верно +1» / «Неверно» для лидера, «Закрыть приём», своя кнопка |
| `result` | видит итог раунда | «Следующий вопрос», «Завершить» |
| `finished` | итоговая таблица | «История», «На главную» |

Переходы:

- `start`: `lobby → question`, раунд 1.
- `open`: `question → buzz_open`, `openedAt = now()`, очередь пуста.
- `verdict(correct)`: лидеру +1, фаза `result`.
- `verdict(wrong)`: статус `wrong`, игрок может нажать снова, фаза остаётся `buzz_open`.
- `close`: `buzz_open → result` без очков.
- `next`: `result → question`, `round += 1`, очередь и вопрос очищены.
- `finish`: из любой фазы кроме `lobby` → сохранить матч → `finished`. Идемпотентно.

### 6.2 Нажатия и тайминги

- Время — **только серверное**, монотонное (`performance.now()`), клиентское не учитывается.
- `buzz` принимается только в `buzz_open`.
- Один игрок не может иметь две записи со статусом `waiting`.
- Rate limit: не чаще одного нажатия в 150 мс на игрока (спам игнорируется).
- Каждое нажатие: `seq` (порядковый номер) и `deltaMs = max(0, now - openedAt)`.
- Порядок — по `seq`. Отображение: лидер `0.00 с`, остальные `+0.42 с` (разница с лидером, 2 знака).
- Нажатия вне окна игнорируются и не создают записей.

### 6.3 Вердикты и очки

- «Верно» — ровно **+1 очко**.
- Вердикт ставится только лидеру (первая запись `waiting`).
- Повторный вердикт по той же записи игнорируется (идемпотентность).
- «Неверно» — отметка ✗, игрок в конец очереди при следующем нажатии.
- Рейтинг: очки ↓, затем верных ответов ↓, затем сумма `deltaMs` верных нажатий ↑, иначе ничья.

### 6.4 Крайние случаи

| Случай | Поведение |
|---|---|
| Игрок обновил страницу | `playerId` в `localStorage` → входит в ту же запись, очки и место сохраняются |
| Ведущий обновил страницу | `adminKey` в `localStorage` → права сохраняются |
| Поздний вход в игре | 0 очков, участвует со следующего раунда |
| Ноль нажатий | «Закрыть приём» без очков |
| Все ответили неверно | ведущий жмёт «Следующий вопрос» |
| Одинаковые ники | уникальность без учёта регистра, ошибка «Ник уже занят, попробуйте “Ник2”» |
| Перезапуск сервера | комнаты в памяти теряются, история на диске остаётся |

## 7. Протокол Socket.IO

Все клиентские вызовы — с ack: `{ ok: true, data }` или `{ ok: false, error: { code, message } }`.

**Клиент → сервер:**

| Событие | Payload |
|---|---|
| `room:create` | `{ roomName, nick, playerId }` → `{ code, playerId, adminKey }` |
| `room:join` | `{ code, nick, playerId }` → `{ state }` |
| `room:leave` | `{ code, playerId }` |
| `buzz` | `{ code, playerId }` → `{ deltaMs, position }` |
| `admin` | `{ code, adminKey, action: 'start'\|'question'\|'open'\|'verdict'\|'close'\|'next'\|'finish', data? }` |

**Сервер → клиент:**

| Событие | Payload |
|---|---|
| `state` | полный срез комнаты — отправляется при **любом** изменении |
| `error` | `{ code, message }` |
| `room:closed` | `{ reason }` |

Правила:

- Один тип события `state` вместо десятка инкрементальных — меньше кода и рассинхрона.
- Клиент никогда не считает очки и порядок, только рисует `state`.
- `state` содержит: `code`, `roomName`, `phase`, `round`, `question`, `openedAt`, `serverTime`, `players[]`, `queue[]`, `lastVerdict`, `standings`.
- Текст вопроса виден всем (ведущий всё равно читает его вслух) — зафиксировать в DECISIONS.
- `playerId` — `crypto.randomUUID()` на клиенте, хранится в `localStorage`.
- `adminKey` — 32 байта hex на сервере, хранится в `localStorage` по ключу `quiz:admin:<code>`.
- Ошибки: `FORBIDDEN`, `ROOM_NOT_FOUND`, `NICK_TAKEN`, `INVALID_STATE`, `VALIDATION`, `ROOM_FULL`, `RATE_LIMITED`.
- Любой входящий payload валидируется вручную (типы, длины, диапазоны), сервер не падает от мусора.

## 12. Тесты и критерии приёмки

`npm test` = `node --test`, без сети и без флаков.

**Unit (`test/game.test.js`)** — игровое ядро с инжектируемым временем:

- переходы фаз и запрет действий не в той фазе;
- порядок очереди по `seq`, `deltaMs`, клампинг;
- нельзя две `waiting`-записи, rate limit 150 мс;
- `correct` → +1 и `result`;
- `wrong` → можно нажать снова, лидер меняется;
- идемпотентность `finish` и повторного вердикта;
- рейтинг и тай-брейки.

**Integration (`test/integration.test.js`)**:

- сервер на эфемерном порту + 3 клиента `socket.io-client`;
- create → join ×3 → start → open → buzz ×3 → verdict → next → finish;
- без `adminKey` → `FORBIDDEN`;
- история появилась в `data/history.test.json` (отдельный файл для тестов).

**Чек-лист готовности:**

1. `npm ci && npm start` работает на чистой копии.
2. `npm test` зелёный.
3. Два браузера создают/входят в комнату и видят друг друга.
4. Кнопка неактивна до «Принимаю ответы», нажатия вне окна игнорируются.
5. Порядок и тайминги одинаковы у всех (±1 мс), лидер `0.00 с`.
6. «Неверно» → ✗ и конец очереди, можно нажать снова; «Верно» → +1 у всех.
7. «Завершить» → итоговая таблица + запись в `data/history.json`.
8. История видна после перезапуска сервера и удаления файла.
9. Обновление страницы игроком и ведущим не теряет права/очки.
10. 360×640 — нет горизонтального скролла, кнопка достижима большим пальцем.
11. В DevTools нет внешних сетевых запросов.
12. README позволяет человеку без контекста запустить игру.
