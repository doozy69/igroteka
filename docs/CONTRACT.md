# Контракт платформы

Контракт намеренно маленький. Игра и портал не знают друг о друге ничего, кроме нескольких URL и записи в реестре. Чем меньше контракт, тем дешевле добавить следующую игру.

## 1. Реестр `games.json`

Единственный источник данных для портала и лаунчера.

```json
{
  "title": "Игротека",
  "tagline": "Один экран. Три игры. Один вечер.",
  "port": 8080,
  "games": [
    {
      "id": "100k",
      "title": "100 к одному",
      "tagline": "Командная викторина на популярные ответы",
      "description": "Ведущий открывает вопросы...",
      "dir": "games/100k",
      "port": 8101,
      "players": "2–8",
      "duration": "40–60 мин",
      "tags": ["команды", "викторина"],
      "accent": "#f0b429",
      "monogram": "100",
      "status": "ready"
    }
  ]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | уникальный ASCII-slug: логи, `data-game`, будущие URL |
| `title` | да | название на карточке |
| `tagline` | да | одна строка под названием |
| `description` | да | 1–2 предложения |
| `dir` | да | путь от корня платформы, например `games/100k` |
| `port` | да | фиксированный порт `8104–8199` для новых игр |
| `players` | да | строка, например `2–8` |
| `duration` | да | строка, например `40–60 мин` |
| `tags` | да | 2–4 коротких тега |
| `accent` | да | цвет карточки, HEX |
| `monogram` | да | 1–3 символа на плитке |
| `status` | да | `ready` или `soon` |

`status: "soon"` означает «скоро»: карточка видна, но ссылка неактивна. `online` в ответе портала — вычисляемое поле, в файле его быть не должно.

**Добавление игры — это только новая запись в `games.json`.** Если приходится править JS портала, контракт нарушен.

## 2. Как запускается игра

Игра — самостоятельный Node-проект:

```bat
cd games/<id>
npm install
npm start
```

Требования:

- `package.json` с рабочим `npm start`;
- сервер читает `process.env.PORT` и слушает `0.0.0.0`;
- без платформы игра открывается на своём порту и полностью работает;
- статика и WebSocket живут в корне своего origin, без предположения о подпути;
- папки `questions/` и `data/` находятся внутри игры.

Порт по умолчанию в конфиге игры должен совпадать с `games.json`. Лаунчер всегда передаёт `PORT`, поэтому расхождение проявится только при одиночном запуске.

## 3. HTTP-эндпоинты

Обязательных эндпоинтов нет: портал проверяет доступность игры TCP-подключением к порту. Но два эндпоинта сильно упрощают жизнь.

### `/api/health`

Рекомендуется. Ответ:

```json
{
  "status": "ok",
  "game": "100k",
  "uptime": 123,
  "rooms": 0
}
```

Портал его не требует, но человеку и диагностике он полезен. Не отдавай в нём секреты.

### `/api/net`

Рекомендуется, если игра показывает QR или адрес для гостей. Ответ:

```json
{
  "ip": "192.0.2.10",
  "port": 8101,
  "addresses": ["192.0.2.10"]
}
```

Зачем: ведущий обычно открывает игру на `localhost`, а гостям нужен LAN-IP. Если строить join-URL из `location.origin`, QR будет вести на `localhost` и не сработает с телефона. Правильно: сервер определяет LAN-IP и отдаёт его клиенту.

### `/qr?text=...`

Не обязателен. Если игра рисует QR, текст ссылки должен быть публичным LAN-адресом, а не `localhost`.

## 4. Границы кода

Разрешено:

- всё внутри `games/<id>/`;
- собственные зависимости и `node_modules`;
- собственные `data/`, `questions/`, тесты.

Запрещено:

- импортировать файлы из другой игры;
- читать `data/` или `questions/` другой игры;
- менять `apps/portal` ради одной игры;
- добавлять зависимость в корень платформы;
- полагаться на конкретный порт другого приложения.

Общий код появится только в `packages/`, когда дублирование станет реальной болью. Тогда это отдельное архитектурное решение, а не побочный эффект задачи.

## 5. Порты

| Диапазон | Назначение |
|---|---|
| `8080` | портал |
| `8101–8103` | текущие игры |
| `8104–8199` | новые игры |

Порт фиксирован: на него ссылаются карточка, QR и документация. Автопоиск порта при платформенном запуске выключен. Если порт занят, лаунчер падает с понятной ошибкой, а не меняет адрес молча.

## 6. Проверка контракта

```bat
npm run validate
```

Скрипт проверяет обязательные поля `games.json`, уникальность id и портов, наличие папок, `package.json`, `npm start` и `AGENTS.md`. Он не проверяет механику игры — только границы платформы.

## 7. Чек-лист новой игры

- [ ] `games/<id>/` — отдельный проект с `package.json`.
- [ ] `npm install && npm start` работает без платформы.
- [ ] `PORT` из окружения учитывается.
- [ ] Сервер слушает `0.0.0.0`.
- [ ] `games.json` содержит корректную запись.
- [ ] Портал показывает карточку и статус без правок своего кода.
- [ ] QR/join-ссылка использует LAN-IP, а не `localhost`.
- [ ] Данные лежат внутри игры.
- [ ] Нет импортов из других игр.
- [ ] Обновлён `AGENTS.md` игры.
