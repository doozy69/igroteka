# AGENTS.md — платформа «Игротека»

Это корень платформы из независимых игр. Твоя задача почти всегда находится **в одной папке**. Не читай чужие игры «на всякий случай»: это тратит контекст и повышает риск сломать чужой проект.

## Порядок чтения

1. Этот файл.
2. `docs/CONTRACT.md` — если задача касается новой игры, порта или `games.json`.
3. `AGENTS.md` внутри нужного приложения.
4. Только после этого — код нужного приложения.

## Карта

| Путь | Что это | Когда трогать |
|---|---|---|
| `apps/portal/` | общая панель, карточки, QR, статусы | задачи про общую страницу |
| `games/100k/` | игра «100 к одному» | задачи только про неё |
| `games/svoy/` | игра «Своя игра» | задачи только про неё |
| `games/quiz/` | игра «Кто быстрее» | задачи только про неё |
| `games/_template/` | шаблон новой игры | создание новой игры |
| `games.json` | реестр игр | добавление/переименование игры |
| `tools/start-all.mjs` | лаунчер платформы | задачи про запуск и порты |
| `docs/` | архитектура, контракт, инструкции | читать, обновлять при изменении контракта |

## Правила

- **Одна задача — одна папка.** Если задача про игру, работай только в `games/<id>/`. Если про панель — только в `apps/portal/`. Если про запуск — в `tools/`.
- **Не импортируй код между играми.** Общего кода пока нет. Если он понадобился, сначала предложи `packages/` и обоснуй, не создавай скрытую связь.
- **Не меняй чужие игры** ради удобства своей задачи.
- **Каждая игра запускается сама по себе** через `npm start` в своей папке. Это главный тест границы.
- **Данные принадлежат игре.** `questions/` и `data/` не покидают папку игры. Портал к ним не обращается.
- **Порт фиксирован** в `games.json` и в конфиге игры. Не включай автопоиск порта для платформенного запуска.
- **Не добавляй общие зависимости** в корень. Зависимости ставятся внутри приложения.
- **Не удаляй `data/`** без явного запроса: там может быть история игр.
- **Не выставляй игры в интернет.** Авторизации нет, это LAN-платформа.

## Публикация в публичный репозиторий

Это обязательное правило перед каждым `git push`, релизом или загрузкой архива в публичный репозиторий.

- Пройди по проекту и удали **все личные данные**: email, имена, ники, номера телефонов, LAN-IP, локальные пути, названия чужих проектов, токены, пароли, ключи.
- Проверь не только код и Markdown, но и **изображения и скриншоты**: имена в интерфейсе, адреса, QR-коды, переписка, уведомления.
- Не коммить `.env`, `data/`, `logs/`, историю игр и реальные конфиги с секретами. Используй placeholder-значения.
- Email автора коммита должен быть GitHub noreply, а не личный.
- Если личные данные уже попали в коммит — перепиши историю и сделай force-push. Если репозиторий публичный и старый коммит остаётся доступен по SHA, удали репозиторий и создай его заново с чистым коммитом.
- После очистки ещё раз проверь `git grep`, список файлов и историю коммитов. Только потом пушь.

## Команды

```bat
:: вся платформа
start.bat

:: проверка реестра и структуры
npm run validate

:: одна игра без платформы
cd games\100k
npm install
npm start
```

Фронтенд в `public/` перезапуска не требует: достаточно обновить вкладку. После изменений серверного кода перезапустите платформу или запустите игру отдельно.

Порты: портал `8080`, игры `8101`, `8102`, `8103`. Новые игры — `8104–8199`.

## Новая игра

1. Прочитай `docs/NEW_GAME.md`.
2. Скопируй `games/_template` в `games/<id>`.
3. Добавь запись в `games.json`.
4. Не меняй код портала: он обязан показывать новую игру из данных.

Если для новой игры **требуется** правка портала, значит контракт нарушен. Остановись и опиши, чего не хватает в контракте.

## Изменение контракта

Меняешь поля `games.json`, схему health-ответа, способ запуска или правило портов — обнови:

- `docs/CONTRACT.md`
- `docs/ARCHITECTURE.md`, если решение архитектурное
- `README.md`, если меняется быстрый старт

Не расширяй контракт «на будущее». Только под реальную задачу.
